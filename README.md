## 🌟 چرا تخت جمشید؟

پروژه‌های مشابه زیادی هستند (نهان، نوا، ادج‌تونل، زئوس)، اما بیشتر آن‌ها یا
**تک‌فایل چند هزار خطیِ Minify‌شده** اند یا **هسته‌شان بسته** است. تخت جمشید با سه هدف ساخته شده:

| هدف | یعنی چه |
|---|---|
| 🧱 **معماری ماژولار** | کد در ۱۰ فایلِ جداگانه و خوانا در `src/` نوشته شده و بعد با `node build.js` به یک فایل تجمیع می‌شود. هر بخش را می‌توانید بخوانید و تغییر دهید. |
| 🎨 **هویت بصری مستقل** | تم اختصاصی الهام‌گرفته از تخت جمشید: طلایی، لاجوردی، فیروزه‌ای، با فرِ بال‌دار و کتیبه‌ی کنگره‌ای — نه یک قالب عمومیِ دیگر. |
| ✅ **تست‌پذیری** | کد با شبیه‌ساز رسمی کلودفلر (Miniflare) آزموده می‌شود: ۸۴ تست یکپارچه + ۹ تست تولید QR در برابر کتابخانه مرجع. |

چیزی که **نیست**: هیچ داده‌ای از کاربران شما جمع نمی‌شود، هیچ سرور واسطی ندارد،
هیچ تماس home‌ـی با سرویس شخص ثالث ندارد (به‌جز وقتی خودتان ربات تلگرام را فعال کنید).

## ✨ ویژگی‌ها

### هسته شبکه
- پروتکل **VLESS** و **Trojan** روی WebSocket + TLS، به‌صورت همزمان یا جداگانه
- احراز هویتِ Trojan بر پایه‌ی **SHA-224** (پیاده‌سازیِ داخلی؛ WebCrypto از آن پشتیبانی نمی‌کند)
- **Early data** (داده‌ی زودهنگام) از طریق `Sec-WebSocket-Protocol` برای کاهش تأخیر
- پشتیبانی از TCP و **DNS روی UDP** (از طریق DoH؛ ترافیک UDP غیرـDNS روی Workers ممکن نیست)
- خروجی مستقیم، یا از طریق **ProxyIP** (سرور واسط VLESS/Trojan) یا **SOCKS5**
- تشخیص کاربر از روی UUID (در VLESS) یا رمز عبور (در Trojan)، و نیز از روی توکنِ مسیر
- **کلید قطع اضطراری (Kill Switch)** برای توقف فوری کل ترافیک
- تولید **آدرس‌های جایگزین روی ۷ پورت** استاندارد کلودفلر

### مدیریت کاربران
- کاربران نامحدود، هر کدام با **لینک اشتراک اختصاصی** و کد QR
- **سهمیه حجمی** (GB/TB)، **تاریخ انقضا**، **محدودیت دستگاه**، یادداشت
- غیرفعال‌سازی خودکار هنگام اتمام حجم یا سررسید تاریخ
- صفر کردن مصرف، فعال/غیرفعال کردن، ویرایش دسته‌ای
- شمارش مصرف به‌صورت **دسته‌ای و غیرهمزمان** (کمینه کردن نوشتن روی D1)

### تولید کانفیگ
- خروجی برای **Base64** (v2rayNG و …)، **Clash / Clash Meta**، **Sing-box** و متن خام
- **قالب نام‌گذاری پویا**: `{FLAG} {CITY} {COUNTRY} {PROTO} {NUM} {NAME} {HOST} {DATE}`
- تولید خودکارِ یک نود جداگانه برای هر **آی‌پی تمیز**
- هدر استاندارد `subscription-userinfo` برای نمایش مصرف در کلاینت
- **صفحه وضعیت** برای هر کاربر (حجم، انقضا، QR، لینک‌ها)
- **تولیدکننده QR کاملاً داخلی** — بدون هیچ وابستگی خارجی (پیاده‌سازی ISO/IEC 18004)

### پنل و امنیت
- نشست امضا‌شده با **HMAC-SHA256**، کوکی `HttpOnly` + `Secure` + `SameSite`
- گذرواژه‌ی پنل با **SHA-256 و نمک تصادفی** (هرگز به‌صورت متن ساده ذخیره نمی‌شود)
- **استتار**: صفحه اصلی یک صفحه‌ی مرجعِ ایستا درباره‌ی تخت جمشید است، نه پنل
- گزارش رویدادها (ورود موفق/ناموفق، تغییر تنظیمات، عملیات کاربران)
- **پشتیبان و بازیابی** کامل به‌صورت JSON
- رابط دو‌زبانه (فارسی/انگلیسی) و حالت روشن/تاریک، کاملاً واکنش‌گرا

### ربات تلگرام
`/status` · `/users` · `/add` · `/del` · `/reset` · `/link` · `/pause` · `/resume` · `/help`

## 🚀 نصب (۳ مرحله)

### گام ۱ — ساخت دیتابیس D1

1. وارد [داشبورد کلودفلر](https://dash.cloudflare.com/) شوید.
2. **Storage & databases → D1 SQL Database → Create database**
3. نامی انتخاب کنید (مثلاً `takht-db`) و بسازید.

### گام ۲ — استقرار Worker

1. **Workers & Pages → Create application → Create Worker**
2. نامی بگذارید (مثلاً `takht-e-jamshid`) و Deploy را بزنید.
3. **Edit code** را باز کنید، کد پیش‌فرض را پاک کنید و محتوای فایل
   [`_worker.js`](./_worker.js) را به‌طور کامل Paste کنید.
4. **Save and Deploy** را بزنید.

### گام ۳ — اتصال دیتابیس

1. در صفحه‌ی Worker به **Settings → Bindings → Add binding** بروید.
2. نوع: **D1 database** · نام متغیر: **`DB`** (دقیقاً با حروف بزرگ)
3. دیتابیس ساخته‌شده را انتخاب کنید → Save → Deploy

### گام ۴ — ورود

```
https://<آدرس-ورکر-شما>/takht/dash
```

- نام کاربری: `dariush` (یا `admin`)
- گذرواژه: `admin`

> ⚠️ **بلافاصله** از منوی کلید (🔑) بالای صفحه گذرواژه را تغییر دهید،
> و در تب «تنظیمات»، **مسیر مخفی** را از `takht` به چیز دیگری تغییر دهید و آن را نشانک کنید.

<details>
<summary><b>روش جایگزین: استقرار با Wrangler (CLI)</b></summary>

```bash
npm install -g wrangler
wrangler login
wrangler d1 create takht-db        # شناسه‌ی دیتابیس را در wrangler.toml بگذارید
npm run deploy
```
فایل `wrangler.toml` را پیش از استقرار ویرایش کنید و `database_id` را جایگزین کنید.
</details>

## 🗺️ مسیرها

| مسیر | کاربرد | نیاز به نشست |
|---|:--:|:--:|
| `/` | صفحه‌ی استتار (مرجع ایستا درباره‌ی تخت جمشید) | ❌ |
| `/<route>` | ورودی پروکسی (WebSocket) | ❌ |
| `/<route>/dash` | داشبورد پنل | ✅ |
| `/<route>/login` | صفحه ورود | ❌ |
| `/<route>/logout` | خروج | — |
| `/<route>/api/*` | API داخلی پنل | ✅ |
| `/<route>/sub/<token>` | لینک اشتراک کاربر | ❌ |
| `/<route>/sub/<token>?format=clash` | خروجی Clash | ❌ |
| `/<route>/sub/<token>?format=singbox` | خروجی Sing-box | ❌ |
| `/<route>/sub/<token>?page=1` | صفحه وضعیت کاربر | ❌ |
| `/<route>/tg` | وب‌هوک ربات تلگرام | رازِ تلگرام |

`<route>` به‌طور پیش‌فرض `takht` است و قابل تغییر است.

## ✈️ ربات تلگرام

1. ربات را در [@BotFather](https://t.me/botfather) بسازید و توکن را بگیرید.
2. Chat ID خود را از [@userinfobot](https://t.me/userinfobot) بگیرید.
3. در تب «تلگرام» هر دو را وارد کنید، فعال کنید و ذخیره کنید.
4. دکمهٔ **تنظیم وب‌هوک** را بزنید (آدرس را خودکار از روی دامنه می‌سازد).

**دستورات:**

```
/status                        وضعیت پنل، مصرف کل و کیل‌سوئیچ
/users                         فهرست کاربران با نوار مصرف و روزهای باقیمانده
/add  <نام> <حجم> <روز>        مثال: /add کوروش 30GB 30
/del  <نام>                    حذف کاربر
/reset <نام>                   صفر کردن مصرف کاربر
/link <نام>                    دریافت لینک اشتراک
/pause                         توقف فوری ترافیک
/resume                        ازسرگیری ترافیک
```

## 🌐 شبکه و عبور از فیلترینگ

- **آی‌پی تمیز**: در تب «شبکه» هر خط یک آی‌پی، با فرمت `1.1.1.1#Frankfurt-DE`.
  برای هر آی‌پی یک نود جداگانه در اشتراک ساخته می‌شود (SNI همچنان دامنه‌ی شما باقی می‌ماند).
- **حالت‌های خروجی**:
  - `مستقیم` — Worker خودش به مقصد وصل می‌شود (پیش‌فرض و سریع‌ترین).
  - `ProxyIP` — ترافیک به یک سرور واسط VLESS/Trojan فرستاده می‌شود (`host:port`).
  - `SOCKS5` — عبور از یک پروکسی SOCKS5 (`user:pass@host:port`).
- **Fragment**: طول و فاصله‌ی بسته‌ها برای عبور از بررسی عمیق بسته‌ها (DPI).
- **محدودیت ذاتی**: پلن رایگانِ Workers روزانه **۱۰۰٬۰۰۰ درخواست** مجاز دارد،
  و ترافیک UDP واقعی (تماس صوتی/تصویری) روی Workers پشتیبانی نمی‌شود.

## 🏗️ معماری و ساختار کد

خروجی نهایی یک فایل است، اما توسعه در فایل‌های جدا انجام می‌شود:

```
src/
  01_meta.js       ثابت‌ها، تنظیمات پیش‌فرض، واژگان دو‌زبانه
  02_utils.js      رمزنگاری (SHA-256/HMAC)، base64، uuid، قالب‌بندی
  03_db.js         لایه دسترسی به D1: تنظیمات، کاربران، لاگ، پشتیبان
  04_config.js     تولید کانفیگ VLESS / Trojan / Clash / Sing-box
  05_qr.js         تولیدکننده QR (بدون وابستگی)
  06_telegram.js   ربات تلگرام و فرمان‌ها
  07_proxy.js      هسته پروکسی: تحلیل سرآیند، اتصال خروجی، DoH
  08_ui.js         رابط کاربری (CSS، SVG، صفحات)
  09_api.js        احراز هویت و API پنل
  10_main.js       مسیریاب اصلی و نقطه ورود

build.js          تجمیع src/ در _worker.js
tests/            تست QR + تست یکپارچه روی Miniflare
tools/preview.js  ساخت پیش‌نمایش‌های ایستا
```

**جریان یک اتصال:**

```
کلاینت ──wss──▶ Worker ──▶ تحلیل سرآیند VLESS/Trojan
                       ──▶ شناسایی و اعتبارسنجی کاربر (سهمیه/انقضا)
                       ──▶ connect() به مقصد (مستقیم / ProxyIP / SOCKS5)
                       ──▶ انتقال دوطرفه + شمارش مصرف
```

**شمارش مصرف** در حافظه انباشته و هر ۲۰ ثانیه (یا پس از ۶۴ رکورد) به‌صورت
دسته‌ای با `D1.batch` نوشته می‌شود تا از محدودیت‌های نوشتنِ پلن رایگان عبور نکنیم.

## 🛠️ توسعه

```bash
npm install          # نصب ابزارهای توسعه (Miniflare)
npm run build        # تجمیع src/ در _worker.js
npm test             # اجرای همه تست‌ها
node tools/preview.js# ساخت پیش‌نمایش‌های HTML در preview/
node tests/run.js    # فقط تست‌های یکپارچه
node tests/test_qr.js# فقط تست QR
```

تست‌های یکپارچه با **Miniflare** (شبیه‌ساز رسمی کلودفلر) اجرا می‌شوند و شامل
احراز هویت، مدیریت کاربران، تولید کانفیگ، و حتی یک **اتصال واقعی WebSocket**
به یک سرور TCP محلی هستند.

> نکته: برای مقایسه‌ی QR با پیاده‌سازی مرجع، بسته‌ی `qrcode` لازم است
> (`npm i qrcode`). در نبود آن، تست‌های ساختاری همچنان اجرا می‌شوند.

## 🔒 امنیت

- گذرواژه هرگز به‌صورت متن ساده ذخیره نمی‌شود: `SHA-256(گذرواژه + نمک تصادفی)`
- نشست با HMAC-SHA256 امضا می‌شود و پس از ۱۲ ساعت منقضی می‌گردد؛
  تغییر گذرواژه، همه نشست‌های قبلی را باطل می‌کند
- کوکی با ویژگی‌های `HttpOnly`، `Secure` و `SameSite=Lax`
- API پنل بدون نشست معتبر پاسخ نمی‌دهد
- ورودی‌های کاربر با `escapeHtml` در خروجی HTML پاک‌سازی می‌شوند
- مسیر پنلِ شما (route) در پیش‌فرضِ استتار پنهان است؛ آن را تغییر دهید و نشانک کنید
- توکن اشتراکِ هر کاربر مانند گذرواژه است — آن را عمومی نکنید

> مسئولیت استفاده با خود شماست؛ قوانین حوزه‌ی خود را رعایت کنید.

## ❓ رفع اشکال

| نشانه | علت و راه‌حل |
|---|---|
| همه چیز صفحه‌ی تخت جمشید نشان می‌دهد | طبیعی است؛ پنل در `/<route>/dash` است |
| خطای `DB_MISSING` یا پنل خالی | اتصال D1 وجود ندارد یا نام متغیر دقیقاً `DB` نیست |
| کانفیگ وصل نمی‌شود | میزبان/SNI را بررسی کنید؛ اگر دامنه‌ی سفارشی دارید آن را در تنظیمات وارد کنید |
| کاربر وصل نمی‌شود | سهمیه تمام شده، تاریخ گذشته یا کاربر غیرفعال است |
| کندی یا قطعی | سهمیه ۱۰۰٬۰۰۰ درخواست روزانه را بررسی کنید، یا آی‌پی تمیز اضافه کنید |
| مسیر پنل یادم رفته | مقدار `route` را در دیتابیس D1 (جدول `settings`) ببینید |

## 🤝 مشارکت

خوش‌حال می‌شویم کمک کنید. پیش از ارسال تغییر، [CONTRIBUTING.md](./CONTRIBUTING.md)
را بخوانید؛ خلاصه‌اش:

```bash
npm install
# فقط فایل‌های src/ را ویرایش کنید
node build.js      # تجمیع در _worker.js
npm test           # باید همه سبز باشد
```

نکته‌ی مهم: **`_worker.js` را دستی ویرایش نکنید**؛ CI بررسی می‌کند که خروجی
دقیقاً با پوشه‌ی `src/` هم‌خوان باشد.
